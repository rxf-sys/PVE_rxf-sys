### 2. PBS in VM 201 statt auf Host

Begründung:
- Saubere Trennung Backup vom Hypervisor

- VM separat sicherbar (theoretisch)

Setup: siehe [../02-installation/pbs-vm-setup.md](../02-installation/pbs-vm-setup.md).

### 3. Datastore-Reuse

Beim Datastore-Anlegen in PBS-Web-UI: Option `--reuse-datastore` aktiviert (sdb1 hatte intaktes PBS-Datastore-Layout).

Resultat: alle ~148 Snapshots sofort wieder verfügbar.

### 4. Token rotiert

Alter Token `root@pam!pve` war nach Recovery nicht mehr verfügbar — neuer Token `root@pam!pve-host` erzeugt, in `/etc/pve/storage.cfg` gesetzt, Owner aller Backup-Groups via API auf neuen Token umgestellt.

### 5. Restore aller Guests

```bash
# Aus PBS, jeweils latest Snapshot
for vmid in 100 101 102 103 104 106 107 108 109; do
  LATEST=$(pvesm list pbs --vmid $vmid | tail -1 | awk '{print $1}')
  pct restore $vmid "$LATEST" --storage local-lvm
done

# VMs
for vmid in 200 201; do
  LATEST=$(pvesm list pbs --vmid $vmid | tail -1 | awk '{print $1}')
  qm restore $vmid "$LATEST" --storage local-lvm
done
```

(VM 201 selbst war Sonderfall — neu installiert + Datastore-Reuse, nicht aus altem Snapshot)

## Lessons Learned

- PBS `--reuse-datastore` ist Gold wert
- Disk-Passthrough für Backup-Disks trennt Backup-Storage sauber vom Hypervisor
- Verfügbarkeit Konsolen-Zugriff am physischen Host war kritisch für die Erstrecovery
- Notifications waren NICHT eingerichtet → man merkte den Schaden erst beim manuellen Aufruf
